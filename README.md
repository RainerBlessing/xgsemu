# XGS Emulator

XGS Emulator is an emulator for the XGameStation Micro Edition (XGS ME): an
Ubicom/Parallax SX52 microcontroller running at 80 MHz, with video generated by
the program itself, SRAM, a joystick port and a ROHM BU8763 sound chip. It runs
the compiled demos and games of the XGS ME (`.hex` and `.obj` files). The window
is drawn with SDL2.

## Status

Implemented:

- **CPU**: the SX52 instruction set with exact cycle counts, the real time
  clock/counter (RTCC) with its prescaler, the MODE register and the port
  control registers, and the carry input of ADD/SUB that a program selects with
  the CF fuse.
- **Video**: NTSC video as the program generates it (sync, colour burst, luminance
  and chroma), shown as a 560x525 picture. The colours follow the colour wheel of
  the hardware and are an approximation of a real TV.
- **Sound**: the three channels of the BU8763 in melody mode (sine or square wave,
  envelope, attenuation, master volume), played through SDL2 audio.
- **SRAM** (128 KB) and the **first joystick**.

Missing:

- Interrupts (RTCC overflow, `reti`, `retiw`), `sleep` and the watchdog
- Timers T1 and T2, the comparator and the wakeup/interrupt inputs of port B
- The DTMF/tone mode of the BU8763
- Keyboard and the second joystick

Known limits: the pitch of the sound is based on the nominal master clock of the
BU8763 (5.376 MHz). The XGS ME documentation also mentions 5.736 MHz, which would
make everything about a semitone higher. This is not settled.

## Hardware requirements

The emulator has to execute 80 million clock cycles per second (about 47 million
instructions per second) on **one CPU core**. More cores do not help.

Measured on an AMD Ryzen 7 9800X3D (one of the fastest single core CPUs), without
window and sound, for four of the example programs:

| Build | Speed compared to the real XGS ME |
|---|---|
| Release (`-DCMAKE_BUILD_TYPE=Release`) | 4.3 to 6.6 times faster |
| Debug (the default of the CMake file) | only 1.2 to 2.0 times faster |

So:

- **Use a Release build.** A Debug build is too slow on most PCs to run at 100%.
- With a Release build, a PC with about a third of the single core speed of that
  CPU should still reach 100% (an estimate, not measured). Slow systems such as a
  Raspberry Pi are borderline and untested.
- Memory is no concern (a few MB). A sound device is optional, without it the
  emulator runs silently.
- The window needs an SDL2 renderer with acceleration (OpenGL, Direct3D, Metal,
  ...). Without a GPU, starting with the environment variable
  `SDL_RENDER_DRIVER=software` selects the software renderer.
- Tested only on Linux.

## Building from Source

### Prerequisites

- CMake 3.10 or later
- A C++ compiler with C++11 support
- SDL2
- Git and a network connection when the tests are built (CMake downloads
  GoogleTest), or switch the tests off with `-DBUILD_TESTS=OFF`

### Build Instructions

1. Create a build directory:

```bash
mkdir build
cd build
```

2. Configure the project. Without `CMAKE_BUILD_TYPE` CMake builds the slow Debug
   version, so ask for Release:

```bash
cmake -DCMAKE_BUILD_TYPE=Release ..
```

3. Build:

```bash
cmake --build .
```

4. The executable is `xgsemu` in the build directory.

### Tests

The tests are built together with the emulator and run in well under a second:

```bash
./unit_tests
```

### Additional Build Options

To clean the build directory:

```bash
cmake --build . --target clean
```

For a complete cleanup, remove the build directory:

```bash
rm -rf build
```

To format the sources with clang-format (if it is installed):

```bash
cmake --build . --target format
```

If you have Git installed, you can create distribution archives in the build
directory:

```bash
# Create a ZIP archive from the main branch
cmake --build . --target git-archive

# Create a ZIP archive with version information
cmake --build . --target git-archive-tagged
```

## Running the Emulator

```bash
./xgsemu                        # starts without a program
./xgsemu examples/rem_pac_01.hex
```

The `examples` directory contains compiled demos from the XGS ME disc (a game, 3D
and plane effects, plasma, starfields and more). Rem-Pac starts with the fire
button.

There is no menu and no file chooser. Programs are loaded with the file name on
the command line or with `Ctrl+L`, which loads a `.hex` or `.obj` file (the first
one the file system lists) from the directory that was used last (it is kept in `~/.config/xgsemu` on Linux and
macOS and in `%APPDATA%\XGSEmu` on Windows, and starts as the current directory).

## Controls

| Key | Action |
|---|---|
| Arrow keys | Joystick directions |
| Left or right Ctrl | Fire button |
| F5 | Reset |
| F11 | Full screen on/off |
| Ctrl+L | Load a `.hex`/`.obj` file from the last used directory |
| Esc | Quit |
